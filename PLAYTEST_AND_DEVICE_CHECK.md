# Remaining real-world validation

Automated checks cannot establish human difficulty, subjective sound quality,
Android frame pacing, battery use, or real AdMob delivery. No APK is built by
this task, per the user's standing instruction. These checks require the user's
phone and volunteers; no results are fabricated.

For five first-time players, observe without explaining the controls:
1. Start level 1, watch/skip the intro and complete the first rescue.
2. Tap then drag a group; identify the available destinations.
3. Play normal, hard and recovery rounds around levels 18–30.
4. Respond to a witch target warning, then clear a seal with two legal moves.
5. Open Rescue home, identify the next unlock, then return to Play.
Record where guidance was needed, confusion, abandoned rounds and reactions to
the meow/witch sounds. Keep hard-level move budgets unchanged until human data
supports retuning; the existing solution certificates are not optimality proofs.

Local-only aggregate counters are saved separately from progress at
`user://playtest_metrics.json`: attempts, wins/losses, active seconds, moves,
hints, undos and rewarded-video outcomes. No names, identifiers or network calls.
On this Windows setup, the user directory remains
`AppData/Roaming/Godot/app_userdata/Cat Sort Lab`. Tests disable persistence.

On the phone: test small/large portrait screens and a notch; check 11/12-tube
boards and minimum touch targets; play for 15 minutes to observe heat/battery;
switch apps mid-drag, intro and reward; disable network; cancel a reward;
complete one test reward; confirm only the earned callback grants it. Test real
SDK presentation/dismissal because a desktop mock cannot validate ad delivery.

Audio role levels are documented in `video_work/runtime_audio_audit.json`.
The native Cat Effects bus has a -1 dB limiter; voices/music use separate volume
preferences. Video's original soundtrack/mix is unchanged by runtime balancing.
